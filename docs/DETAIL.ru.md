# dsh-tauri — Подробное руководство

> Этот документ представляет собой добросовестную компиляцию на основе `README.md` и `docs/DEVELOPMENT.md` из этого репозитория, призванную быстро рассказать о позиционировании проекта, архитектуре, зависимостях и установке, конфигурации, использовании, командах проверки, а также известных ограничениях / границах. Блоки кода, идентификаторы, числа, пути и команды сохранены без изменений.

## 1. Позиционирование проекта

Настольный клиент для [DeepSeek Harness](https://github.com/deepseek-ai), построенный на **Tauri 2**: окно, трей, меню и нативные возможности обеспечиваются Rust + системным WebView, а сам Harness запускает официальный npm-пакет `@deepseek-ai/dsh`, то есть чистый Node-сервис, стоящий за `dsh web`.

**Ни Electron, ни DSH Desktop устанавливать не нужно.** Один `node` и одна копия `node_modules/@deepseek-ai/dsh` — это вся среда выполнения.

### Главная цель

**Цель:** приоритет отдаётся Linux — всем дистрибутивам и версиям — с целью обеспечить максимальную совместимость, производительность и минимальное потребление ресурсов. Остальные платформы, поддерживаемые фреймворком (Tauri 2), в принципе предполагаются для базовой поддержки, без глубокой адаптации или оптимизации.

> **Текущее состояние (фактическое):** пока адаптирован и проверен только Linux (код опирается на собственные команды Linux `zenity` / `wl-clipboard` / `notify-send` и проверен только на Linux + WebKitGTK 2.52; совместимость с множеством дистрибутивов остаётся целью, а не полностью проверенным фактом). Windows и macOS ещё не завершили адаптацию, и сборка и запуск там не гарантированы. Мобильные платформы (iOS / Android) пока неприменимы, поскольку архитектура опирается на локальный Node-сервис вместе с системным WebView.

### Чем это отличается от «встраивания Electron-приложения в Tauri»?

Tauri предоставляет лишь системный WebView и Rust-бэкенд; он не поставляет среду выполнения Node. Поэтому ключ не в смене оболочки, а в том, **какое ядро запускается**:

| Подход | Среда выполнения | Результат |
| --- | --- | --- |
| Tauri вокруг каталога установки Electron | app.asar из `/opt/DSH NEXT` (ядро зависит от главного процесса Electron) | Вам по-прежнему приходится реверс-инженерить официальную установку, и она ломается при каждом обновлении выше по потоку |
| **Этот проект** | `@deepseek-ai/dsh` из npm, `dsh web` как обычный Node-процесс | Ядро — публично распространяемый пакет; для обновления достаточно изменить номер версии |

Оболочке остаётся сделать лишь три вещи: поднять сервис, направить на него окно и обеспечить возможности, которых нет у браузера.

## 2. Архитектура

```
┌────────────────────── Tauri 进程（Rust） ──────────────────────┐
│ 托盘 / 菜单 / 窗口状态 / 单实例 / 崩溃重启                      │
│ 原生命令：目录选择、剪贴板、通知、外链、窗口标题                │
│ window ──► http://127.0.0.1:<port>/?token=…                    │
└──────────┬───────────────────────────────────────▲─────────────┘
           │ spawn（stdout 里解析 URL）             │ invoke
┌──────────▼───────────────────────────────────────┴─────────────┐
│ node runtime/node_modules/@deepseek-ai/dsh/lib/bin.js           │
│   --profile web --host 127.0.0.1 --port 0 --no-open             │
│ 官方 Web UI + 插件 + 会话存储（DSH_HOME，默认 ~/.dsh）           │
└─────────────────────────────────────────────────────────────────┘
```

Скрипт внедрения (`src-tauri/src/native.rs::SHIM`) выполняется до скриптов страницы, добавляет `__DSH_DIRECTORY_PICKER__` и `__DSH_TAURI__` (буфер обмена / уведомления / внешние ссылки) и синхронизирует `document.title` с нативной строкой заголовка — WebKit сам этого не делает.

## 4. Сборка и использование

```bash
npm install --prefix runtime @deepseek-ai/dsh   # 仅开发用：让 probe / 本仓库内启动拿到本体
npm test                                        # 运行时契约探针

cd src-tauri && cargo run
```

`cargo run` сам поднимает сервис и открывает его в окне.

Упаковка (deb / AppImage) использует `npx tauri build` и не поставляет `node_modules` вместе с пакетом: **при первом запуске установка выполняется автоматически**, `@deepseek-ai/dsh` устанавливается в `~/.dsh/dsh-tauri/runtime`. В этот момент splash показывает этап (поиск / установка / запуск) и прошедшее время; никакие команды заранее выполнять не нужно.

Оболочка ищет в порядке «`DSH_TAURI_RUNTIME` → `runtime/` внутри репозитория → `~/.dsh/dsh-tauri/runtime`». Только в режиме **offline** нужно один раз установить вручную:

```bash
npm install --prefix ~/.dsh/dsh-tauri/runtime @deepseek-ai/dsh
```

### Автоматические обновления

После поднятия сервиса оболочка запускает фоновый поток, выполняющий `npm view @deepseek-ai/dsh version`. Если версия выше по потоку новее локальной, она автоматически устанавливается в тот же каталог среды выполнения, после чего `notify-send` показывает сообщение «已更新到 <版本>，重启生效».

- **Не прерывает текущую сессию**: работающий сервис не убивается; старый каталог переименовывается в `<runtime>.old-<pid>` и сохраняется для него, а новая версия загружается только при **следующем запуске**
- **При ошибке молча повторяет попытку**: неудачная проверка или установка записывает только одну строку в журнал (`[runtime] 更新检查失败（下次启动再试）`), не показывает всплывающего окна, не влияет на использование и повторяется при следующем запуске
- **Обновляет только каталоги, установленные ею самой**: каталог, заданный `DSH_TAURI_RUNTIME`, и `runtime/` внутри репозитория принадлежат пользователю или git; оболочка лишь пишет в журнал и никогда туда не пишет файлы

Ручное обновление по-прежнему возможно — это равносильно тому, что оболочка его не делает:

```bash
npm install --prefix ~/.dsh/dsh-tauri/runtime @deepseek-ai/dsh@latest
node tools/probe-web.mjs --runtime ~/.dsh/dsh-tauri/runtime   # 升级后先验契约
```

### Порядок поиска среды выполнения

`DSH_TAURI_RUNTIME` → `runtime/` внутри репозитория (учитывается только при наличии `node_modules`) → `~/.dsh/dsh-tauri/runtime` → `runtime/` в каталоге упакованных ресурсов.

Если ничего не найдено, показывается страница ошибки с командой установки в тексте.

`runtime::Source` запоминает, какой уровень сработал. Только `Home` и `Resource` — собственные каталоги оболочки, в которые могут писать автоматические обновления; `Explicit` (`DSH_TAURI_RUNTIME`) и `Checkout` (внутри репозитория) получают лишь строку в журнале и никогда не трогаются — там могут находиться файлы, отслеживаемые git.

### Автоматическая установка при первом запуске

Когда `runtime::ensure` не находит среду выполнения ни на одном из четырёх уровней и режим не offline, он вызывает `install::install(dir, "latest")`, устанавливая в `~/.dsh/dsh-tauri/runtime`:

```
runtime::ensure          定位失败 → 非离线 → install_fresh
  install::npm_available 先跑 `npm --version`，缺 npm 给可读错误
  swap::Staging::new     建 <runtime>.new-<pid> 暂存目录（先清掉旧的临时树）
  exec::run              npm install --prefix <staging> --no-audit --no-fund
                          --loglevel=error @deepseek-ai/dsh@latest（600 秒超时）
  has_package            校验 node_modules/@deepseek-ai/dsh/lib/bin.js 存在
  Staging::commit        rename 换上去，旧的改名 .old-<pid>
```

- Во время установки выставляется `progress::set(Stage::Installing, …)`, а splash опрашивает `runtime_status`, чтобы показать этап и прошедшее время;
- `exec.rs` запускает npm в отдельной сессии и по таймауту или при выходе убирает всю группу процессов целиком, не оставляя дочерних процессов `postinstall`;
- Любой сбой возвращает читаемую ошибку вместе с ручной командой через `progress::fail` → страница ошибки.

### Реализация автоматического обновления

После запуска сервиса `update::spawn_once(dir, source)` стартует поток `dsh-update` (один раз на процесс):

1. `version_at(dir)` читает версию из локального `node_modules/@deepseek-ai/dsh/package.json`;
2. `npm view @deepseek-ai/dsh version` получает версию выше по потоку (таймаут 90 секунд, с учётом пользовательской настройки зеркала npm);
3. `version::is_newer` сравнивает (чисто семантическое сравнение на Rust, включая правила prerelease; см. юнит-тесты в `version.rs`);
4. При наличии обновления: `progress::set(Stage::Updating, …)` → `install::install(dir, "latest")` проходит тот же путь staging + атомарной замены → `notify-send -a DSH "DSH 已更新" "已更新到 x.y.z，重启生效"`.

Ограничения: не убивать работающий сервис (новая версия загружается только при следующем запуске), при ошибке выводить только `[runtime] 更新检查失败（下次启动再试）` и повторять попытку при следующем запуске, а когда `Source::updatable()` ложно — записать только одну строку в журнал.

### Атомарная замена и очистка

- Каталог staging `<runtime>.new-<pid>` и старое дерево `<runtime>.old-<pid>` — **родственные каталоги** среды выполнения, благодаря чему `rename` остаётся в одной файловой системе и атомарным;
- `commit` сначала переименовывает старый каталог в `.old-<pid>`, затем перемещает staging на его место; если второй шаг не удался, старый каталог переименовывается обратно (сообщение об ошибке гласит «旧运行时已恢复»);
- `Staging::drop` удаляет дерево staging, если commit не состоялся — прерванная установка не оставляет недоделанного продукта;
- Старое дерево **сохраняется для ещё работающего сервиса** (его модули загружены из старого дерева), поэтому после обновления на диске одновременно находятся две копии (около 1.2G); `swap::clean_stale_runtime()` вызывается в `.setup` файла `main.rs` после захвата блокировки одного экземпляра и очищает все родственные каталоги `<name>.new-*` / `<name>.old-*`, записывая в журнал только ошибки.

## 5. Конфигурация и переменные окружения

`cargo run` сам поднимает сервис и открывает его в окне. Частые переопределения:

| Переменная | Назначение |
| --- | --- |
| `DSH_TAURI_RUNTIME` | каталог среды выполнения (содержащий `node_modules`) |
| `DSH_TAURI_NODE` | исполняемый файл node |
| `DSH_TAURI_HOST` | хост, к которому привязывается сервис, только loopback (по умолчанию `127.0.0.1`; допустимы `localhost` / `::1`) |
| `DSH_TAURI_NPM` | путь к исполняемому файлу npm (по умолчанию npm из PATH; используется автоматической установкой/обновлением и определением версии) |
| `DSH_TAURI_PROFILE` | какой профиль запускать (по умолчанию `web`) |
| `DSH_HOME` | каталог данных (по умолчанию `~/.dsh`) |
| `DSH_TAURI_URL` | для разработки: открыть напрямую уже работающий loopback-сервис (только http(s) + 127.0.0.1/localhost/[::1]), не запуская новый |

### Переключатели автоматического обновления (переменные окружения)

| Переменная | Назначение |
| --- | --- |
| `DSH_TAURI_AUTO_UPDATE=0` | отключить проверку версии; автоматическая установка при первом запуске продолжает работать |
| `DSH_TAURI_OFFLINE=1` | отключить всю сетевую активность (установка + проверка); запуск с существующей средой выполнения возможен и без сети |

### Два переключателя (значения и эффекты)

| Переменная | Значения | Эффект |
| --- | --- | --- |
| `DSH_TAURI_OFFLINE` | `1/true/yes/on` | отключить установку и проверку (вся сетевая активность); при отсутствии среды выполнения — страница ошибки |
| `DSH_TAURI_AUTO_UPDATE` | `0/false/no/off` | отключить только проверку версии; автоматическая установка при первом запуске продолжает работать |

Реализация — в `runtime.rs::offline()` / `auto_update_enabled()`; `auto_update_enabled` сначала замыкает `OFFLINE`, поэтому в offline-режиме отключены оба.

## 6. Важные особенности реализации

1. **URL сервиса берётся только из stdout**: `dsh web` печатает `dsh web: http://127.0.0.1:<port>/?token=…`; не угадывайте порт самостоятельно — `--port 0` позволяет системе выделить его.
2. **Окно должно создаваться непосредственно на этом URL, сразу после его получения**. Сначала создать splash-окно, а затем выполнить `navigate` — WebKit потеряет `Set-Cookie` перенаправления аутентификации (симптом: на странице видно только `dsh web authentication required`). Поэтому используется splash-окно с отдельным label; когда URL найден, создаётся новое окно `main`, а splash уничтожается.
3. **Скрипт внедрения должен выполняться до скриптов страницы**: `WebviewWindowBuilder::initialization_script`. Он опирается на `window.__TAURI__.core.invoke`, предоставляемый `withGlobalTauri` (см. `tauri.conf.json`).
4. **Токен в строке запроса — одноразовая точка входа аутентификации**: `GET` возвращает 303 и выставляет cookie `dsh-auth-<authority>` (`HttpOnly; SameSite=Strict`). Сервер формирует имя cookie по authority, поэтому при смене порта оно меняется.
5. **Выход осуществляется через SIGTERM**: `dsh::shutdown()` сначала выполняет `kill -TERM`, и только если через 5 секунд процесс не вышел, применяет SIGKILL, чтобы не оставить остатков WAL в базе сессий.
6. **Выход из трея** должен сначала вызвать `dsh::shutdown()`, а затем `app.exit(0)`, иначе останутся осиротевшие процессы node.

### Отладка автоматической установки и обновлений

**Фейковый npm** (без сети, без загрузки 1.2G; проверяет всю цепочку установки / обновления): `install::npm()` распознаёт `DSH_TAURI_NPM`; достаточно написать исполняемый скрипт, изображающий npm.

```bash
#!/usr/bin/env bash
# /tmp/fake-npm ：DSH_TAURI_NPM=/tmp/fake-npm
set -e
case "$1" in
  --version) echo "10.0.0" ;;
  view)      echo "${FAKE_UPSTREAM:-9.9.9}" ;;          # 假装上游版本
  install)                                              # npm install --prefix X …
    prefix=""; prev=""
    for a in "$@"; do [ "$prev" = "--prefix" ] && prefix="$a"; prev="$a"; done
    pkg="$prefix/node_modules/@deepseek-ai/dsh"
    mkdir -p "$pkg/lib"
    echo '{"name":"@deepseek-ai/dsh","version":"'"${FAKE_LOCAL:-1.0.0}"'"}' > "$pkg/package.json"
    : > "$pkg/lib/bin.js"
    ;;
esac
```

- **Установка при первом запуске**: отведите `~/.dsh/dsh-tauri/runtime` в сторону (`mv` в `/tmp`), запустите `DSH_TAURI_NPM=/tmp/fake-npm cargo run`; splash должен войти в этап «正在安装», а по завершении должен существовать `~/.dsh/dsh-tauri/runtime/node_modules/@deepseek-ai/dsh/lib/bin.js`; у фейкового пакета нет настоящего сервиса, поэтому окно в итоге остановится на ошибке запуска — для проверки цепочки установки этого достаточно.
- **Путь обновления**: после установки задайте `FAKE_LOCAL=1.0.0` и `FAKE_UPSTREAM=2.0.0` и запустите снова; в журнале должны появиться `发现新版 2.0.0（本地 1.0.0）`, `已原子替换`, `旧运行时保留至下次启动清理`, а рядом появится каталог `<runtime>.old-<pid>`; ещё один запуск должен вывести `清理上次运行留下的 …`.
- **Переключатели**: `DSH_TAURI_OFFLINE=1` без среды выполнения → текст страницы ошибки содержит команду `npm install --prefix`; `DSH_TAURI_AUTO_UPDATE=0` → журнал показывает `自动更新已关闭`, но первая установка всё равно выполняется.
- **Ошибка установки**: пусть ветка `install` фейкового npm выполнит `exit 1` → страница ошибки содержит вывод npm и ручную команду, а исходная среда выполнения не затронута (`<runtime>.new-<pid>` удалён через `Drop`).
- **Уборка**: `pkill -x dsh-tauri`; убедитесь, что под `~/.dsh/dsh-tauri/` не осталось `.new-*` / `.old-*`, и не забудьте удалить / вернуть фейковый npm и отведённую среду выполнения.

## 8. Проверено (Linux + WebKitGTK 2.52)

- `dsh web` поднимается оболочкой, `http://127.0.0.1:<port>/?token=…` разбирается из stdout; первый экран появляется в течение 3–30 секунд (в зависимости от кэша);
- Цепочка аутентификации: URL с токеном → 303 + cookie `dsh-auth-*` → `GET /` возвращает HTML клиента (`tools/probe-web.mjs`);
- В окне находится полный Web UI: список сессий, рабочие пространства, выбор модели, страницы плагинов и текущие потоки сессий — всё на месте;
- Окно переименовывается в соответствии с `document.title`; при закрытии соблюдается настройка «закрыть в трей» или «выйти» (настройка — поле `closeToTray` в `~/.dsh/desktop-preferences.json`: `true` = закрыть в трей, `false` = выйти, по умолчанию `true`); размер восстанавливается при перезапуске;
- Второй запуск фокусирует существующее окно и завершается, не поднимая второй сервис;
- Сервис автоматически перезапускается после убийства (не более 3 раз); если снова не удаётся, показывается читаемая страница ошибки;
- При первом запуске без среды выполнения `npm install` автоматически устанавливает её в `~/.dsh/dsh-tauri/runtime`, а splash показывает текущий этап и прошедшее время;
- Сервис запускается автоматически после установки; при наличии более новой версии выше по потоку она устанавливается в фоне, и `notify-send` показывает «重启生效», не затрагивая работающий сервис;
- При `DSH_TAURI_OFFLINE=1` и отсутствии локальной среды выполнения вместо пустого окна показывается страница ошибки с ручной командой;
- Обновления идут через каталог staging `<runtime>.new-<pid>` + атомарную замену, поэтому прерванная установка не повреждает уже установленную среду выполнения.

## 9. Известные ограничения / границы

| Пункт | Текущее состояние |
| --- | --- |
| Встроенный вид страницы платформы (использование / пополнение) | Открывается в браузере; нативная встройка не реализована |
| Старая среда выполнения занимает диск после обновления | Старое дерево переименовывается в `<runtime>.old-<pid>` и сохраняется для ещё работающего сервиса, **очищается только при следующем запуске**; в это время занимается примерно ещё одна копия среды выполнения (около 1.2G) |
| Остатки после SIGKILL | При `SIGKILL` оболочка не успевает убрать дочерние процессы, поэтому дочерние процессы `postinstall` от npm могут недолго оставаться; обычный выход (SIGTERM) не затронут |
| Windows / macOS / мобильные платформы (все остальные платформы, поддерживаемые Tauri) | **В принципе предполагается базовая поддержка**, но сейчас это не главная цель. Текущее состояние: адаптирован и проверен только Linux; Windows и macOS ещё не завершили адаптацию, сборка и запуск там не гарантированы; мобильные платформы пока неприменимы из-за архитектуры с локальным Node-сервисом + системным WebView |
| Положение окна в Wayland | Определяется композитором; `position()` влияет только на композиторы в стиле X11 |
| Ожидание при первом запуске | Этап и прошедшее время видны, но построчного вывода npm нет |
